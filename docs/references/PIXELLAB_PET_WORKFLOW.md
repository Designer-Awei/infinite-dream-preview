# PixelLab 宠物动画：原图到运行资源

这份流程记录当前已采用的制作方法。原始参考图保存在 `art/references/`，最终像素保存在 `web/assets/pets/`；中间素材只在本地 `art/` 工作区。此文和配方足够定位原图、导出已确认参考姿势、查出实际使用的提示词与参数，不需要读取全部历史工作日志。

## 先定位，不遍历全部生成记录

```sh
python tools/pixellab/pet_recipe.py --list --filter follow/dragon --limit 9
python tools/pixellab/pet_recipe.py --list --filter ride/phoenix --limit 6
python tools/pixellab/pet_recipe.py --show follow/dragon-1/move
python tools/pixellab/pet_recipe.py --show ride/phoenix/deepseek/flight
python tools/pixellab/pet_recipe.py --export ride/phoenix/deepseek/flight
python tools/pixellab/pet_recipe.py --check
```

配方 ID 为 `follow/家族-阶段/动作` 或 `ride/家族/角色/动作`。动作包括 idle、move、cast；冰凰骑乘共用 flight 循环。家族为 dragon、phoenix、fox；角色 deepseek=大肥鱼、gpt=吉普缇、grok=格洛克、claude=克劳德、doubao=奶糖包、glm=吉拉姆。不要用界面角色排列顺序推断原图格位。

`--show` 只读取一个配方并展开提示词。配方库按条目保存去重提示词，保存已采用任务的精确英文描述、seed、参数、来源任务哈希、原图链接、准备与清理数据、最终图集坐标和每帧 RGBA 校验值。没有保存凭据、图片 base64、接口完整响应或失败任务历史。`selected_job` 是本地原始记录位置，可在整理前基线提交中追溯，不是新克隆的依赖。

`--export` 离线从最终图集导出 `reference-256.png`、`selected-strip.png`、`recipe.json`，默认放在被忽略的 `art/work/pet-exports/配方ID/`，也可用 `--output art/work/新目录`。禁止覆盖已有导出或写入 `art/references/`。导出的像素与已采用帧完全相同；PNG 编码和压缩方式可能不同，不能用整个 PNG 文件哈希判断像素是否变化。

## 1. 原图、轮廓与画布

1. 在 `art/references/catalog.json` 按用途或 SHA-256 定位原始整张图。旧设计和用户补发的修正图分别存档。当前火龙幼年与终极跟随使用已确认的三形态图；成长体使用用户 2026-11-09 后补图的中间主体（`dragon-growth-user-20261109.png`），从原尺寸直接准备 256 参考并重做三动作，行走要求左前与右后、右前与左后两组对角交替，同侧前后腿反向摆动；攻击与另两形态一致，四爪基本站定，仅轻微屈膝，由头颈、胸部与双翼完成吐息动作；冰凰幼年与成长使用旧整图，终极使用修正远翼的新整图；灵狐保留原设计。配方 `originals` 指向确切来源。
2. 三形态整图按独立主体范围裁切，保留角、尾焰、羽毛尖等完整轮廓。六角色骑乘图按 alpha>32 的完整主体连通域识别，再保留一像素邻接的 alpha>8 边缘；不要直接沿 512 格线硬切，尾巴和翅尖可能越格。`preparation.component.source_box` 或跟随 `preparation.source_box` 提供原图坐标。
3. 输入使用原 PNG alpha。不能按白色抠图：白羽、眼睛高光、衣服和发丝都是主体。不能经过会铺白底的 unzoom。
4. 从高分辨率原图直接准备 **256×256 RGBA** 参考，不能先变为 96/128 再放大。跟随与灵狐骑乘高清流程使用 LANCZOS；龙/凰组合图历史准备流程使用 NEAREST。具体准备结果以配方的尺寸、偏移、锚点和已确认参考像素为准；继续已有动作时优先直接导出参考，避免重新插值产生细微差异。
5. 通常将足底或等效悬浮基线对齐到 `[128,232]`，完整主体留在画布内。跟随体形按原游戏世界尺寸计算 `render_scale`，不同阶段保留大小关系。灵狐骑乘 scale=0.4875；火龙/冰凰骑乘沿用其 JSON。256 是原生帧分辨率，不等于游戏世界中的显示宽度。

参考姿势、裁切后主体与整张原图不是三份必须上传的文件：整图留一份，已确认参考从最终图集首帧恢复。需要修改设计时再由整图重新裁切。

## 2. 使用已采用的提示词与参数生成

当前动画使用 PixelLab `/animate-pixminimax`（历史客户端基础地址为 `https://api.pixellab.ai/v2`）。这是本项目当时实测有效的请求记录，后续服务接口变化应先查服务文档，不盲目重跑旧任务。

请求的 `first_frame` 与 `last_frame` 都是同一张透明 256 参考。通常 `frame_count=12`、`no_background=true`、`direction=east`、`view=side`、`enhance_prompt=false`；具体 seed、drift_threshold、角色描述等取所选配方 `request`。返回实测为 **13 张 256×256**，包含循环端点；不要误认为返回 12 张，也不要把预览图的尺寸当生成分辨率。历史接口拒绝 512 动画输入，不把插值放大的图称作原生 512。

优先使用配方保存的最终提示词，不从旧通用模板猜测当前版本。提示词关注点：

- 火龙跟随：四足着地，双翼同步大幅扇动，展开、下压、翻转、折叠恢复；走路采用对角承重。幼年 move 已修正为两面始终红色翼膜，禁止黄/红交替。
- 冰凰跟随：完整同步翼拍，羽毛翻面与延迟摆动；终极只用已修正远翼的参考。
- 灵狐跟随和骑乘：前左+后右、前右+后左交替；保持原有尾数、金白紫毛色、骑手细节；施法只做身体动作。
- 火龙骑乘：四足步态，翼根和上翼脊位于骑手手部/面部以下，下翼膜向地面卷动后恢复，不能挡脸；具体角色/动作仍以所选请求为准。
- 冰凰骑乘：吉普缇已确认 r6 完整翼拍提示词为基础；其他五名只替换外观描述。臀部与实体背部保持接触，近侧羽毛保持在腿、裙摆前，不能浮空或露出错误腿。大肥鱼采用第5版、Claude第2版、grok/doubao/glm第1版，吉普缇 r6；本次配方保存各版本实际请求。

用户要求“硬抽、不改提示词”时只更换 seed、每次出两版供挑选，不擅自改变已经确认的动作。生成具有随机性：记录 seed 便于追溯，不保证服务将来逐像素重现结果。

凭据继续由已有 `PIXELLAB_KEY_FILE` 指定，在本地读取；密钥、含密钥的响应、base64 图片不写入 docs、日志或仓库。执行新上传/生成时遵守当次用户授权范围。本次整理和导出工具全部离线，不调用 PixelLab。

## 3. 清理与验收

1. 保留服务 raw、任务 JSON、失败候选和验收板在本地忽略目录；原始返回不覆写。每个版本有独立名称，再明确选择采用版本。
2. 逐张检查确为 256×256、13 张；首尾替换为透明原参考，保持中间帧原生成顺序，不能用倒序回放拼出“完整翼拍”。保存条带为 3328×256；组合时直接复制 RGBA 像素，不用重复 alpha 遮罩粘贴造成边缘变淡。
3. 一般清理 alpha<=8 的残点及很小的独立碎片，跟随通常阈值32像素；部分骑乘为128。不得无差别删除白色、浅粉色或相连细节。配方 `cleanup` 保留该版本实际规则；点状修复坐标来自已确认结果。
4. 吉普缇冰凰第4/5/6/7帧羽毛缝残点按 ROI 和逐像素坐标修正，其他白羽高光不动；大肥鱼/吉拉姆等有各自小范围清理。灵狐移除生成器添加的独立外部环，不增加嘴部贴图特效。
5. 至少查看静态逐帧板与循环播放：坐姿、手与膝盖识别、近远腿、翼膜颜色、双翼相位、脚步对角交错、全身基线和大小、尾巴、透明缝、外轮廓安全边距。自动检查不能取代这一步。

## 4. 打包、接入与验证

跟随最终文件为 `pets.png`、`pets-fox.png` 和 `pets.json`；三家族骑乘分别为 `{dragon,phoenix,fox}-mounted.png/.json`，都位于 `web/assets/pets/`。每格256，两边不超过4096。相同参考帧可共享坐标；冰凰骑乘 idle/move/cast 共用每个角色同一完整周期，切换状态不重置相位。不要重新收录已淘汰的128帧、前后腿拼接资源或旧候选图集。

元数据记录帧坐标、帧大小、世界缩放、锚点与嘴部坐标。火龙指向线和真实火球从同一个稳定龙嘴锚点发出，不跟随头部动画抖动改变瞄准路径；灵狐电弧起点每帧随当前嘴部、世界位置与朝向重新计算。火球、龙卷、雷电等战斗效果由代码处理，不烘焙进动物动画。

```sh
python test/asset-policy.py
python tools/pixellab/pet_recipe.py --check
npm run build
```

`asset-policy.py` 在没有任何本地中间素材的源码包中也能执行：校验原图去重与哈希、69条配方、897帧像素、最终web/docs资源一致，以及离线导出和路径限制。它不调用外网。运行构建只需最终 `web/`，现有脚本生成 `dist/` 并刷新 `docs/` 发布副本，保留 `docs/references` 与 `docs/rules`。

现存 `followers_hd.py`、`fox_mounts_hd.py`、`animate_riding_v2/v3/v4.py`、`phoenix_flight.py`、`finalize_phoenix_gpt.py` 等为实际算法参考。旧 prepare/pack、旧 `test/fox-hd-assets.py` 等源图审计需要本地 `art/pets/...` 与某些旧Git提交，**不是全新源码包的构建步骤**。不要在干净克隆中直接执行旧发布命令；从本配方导出、准备新的忽略工作目录后，再适配任务/打包脚本。

新动作通过人工验收后，同步更新运行图集、坐标与嘴部元数据、配方中的请求/像素校验，保留新的原图设计，再按 [素材规则](../rules/ASSETS.md) 验证、记日志并提交。中间文件继续只保留本地。
