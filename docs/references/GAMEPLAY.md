# 无限梦境 · Infinite Dream Preview

本仓库是「无限梦境」的提前测试版本，用于为[正式版](https://github.com/Designer-Awei/infinite-dream)探索新功能、尝试玩法改动并进行测试验证。新功能会先在预览版中试验，根据测试结果调整完善后，再考虑同步到正式版。预览版内容可能随测试发生变化。

像素风地牢肉鸽（元气骑士式闯关 + 荒野乱斗式地图与操作）。六位角色：大肥鱼、吉普缇、格洛克、克劳德、奶糖包、吉拉姆。
浏览器打开即玩，无需注册；手机横屏支持虚拟摇杆；2~4 人联机合作或竞技场 PVP。

- 操作：电脑 WASD 移动 · J 攻击（范围内自动吸附锁敌）· K 技能 · L 大招 · 空格闪避；手机左侧摇杆 + 右侧技能键（轻点自动瞄准，拖动手动瞄准）。
- 闯关：三张主线地图（数据草原 / 显存冰原 / 算力熔炉）与无尽回廊。一局 7 个房间：战斗 → 战斗 → 补给站 → 精英战 → 战斗 → 补给站 → 地图首领。清场开箱三选一技能卡，借用其他角色的弹幕与技能触发元素反应。
- 梦境裂隙：无尽模式挖宝后返回当前进度继续闯关，不会提前结算；所有战斗模式的裂隙窗口均可“放弃进入”，每次放弃在本局最终结算额外获得 200 晶石，无尽中可累计，进入裂隙不领取这项奖励。
- 无尽补给站：可抽技能卡全部达到上限后，抽卡机器对该角色直接消失，不再扣币或打开空选卡界面；空补给箱奖励自动跳过，传送门照常开放。合作按各自卡池判断。
- 梦境矿场：用铲子下潜挖矿，带回晶石、矿石、星砂；矿场装备升级、梦境工坊（最终减伤、SSR 兑换卡、角色梦核）、每日委托。
- 局外养成：晶石扭蛋（永久天赋，SSR 天赋装配到角色）、角色梦核、怪物图鉴，以及各地图稀有怪物掉落的梦境藏品。

## 无尽分阶段难度（预览版）

- 1–30层保留轻松开荒节奏，31–60层承接约35层成型的卡牌构筑，61层后加速提升，120层作为当前版本强构筑的挑战目标，不设硬性封顶。怪物生命/伤害用平滑阶段曲线；算力方块前40个保持完整收益，之后递减但持续有效，人物与宠物共用同一增伤。元素反应的额外楼层系数在35层停涨。主线和竞技场原数值不变。[公式、假设与实测](ENDLESS_STAGE_BALANCE.md)。
- 卡池抽空后，无尽战斗房清场直接开传送门，不再生成宝箱；合作队友仍有可选卡时保留奖励。补给站空卡池机器继续隐藏且不扣钱。
- 工坊兑换卡可兑换1级未满SSR或1积攒点；积攒点右侧预览沿用扭蛋机渐变背景，左条为当前值、右条循环增长+1，中间显示点数变化，不展示机器，预览不消耗资源；兑换按钮使用2px黑色轮廓线、无文字投影；兑换卡列表保留外框高度，内部卡片与常驻扭蛋展示卡同高，第二排部分露出并可向下滑动；未满级SSR和积攒点自动前移，每次兑换后重新排序；音效/音乐开启显示绿色、关闭灰色；冰原与熔炉首页卡片去掉倍率文字，完整显示通关数，实际收益不变。

吉普缇小技能的移动减速仅在1.2秒吐息期间生效，结束恢复原移速；骑乘、重复施法与合作同步一致，永久移速加成保持。

## 梦境航线（预览版 · 第一阶段）

- 单人主线每局生成一张 7 层分支路线：每清一层，在 2～3 个房间里选下一间；第 1 层固定战斗，第 7 层固定首领，第 3 或第 6 层至少有一个补给站，第 4 或第 5 层至少一个精英。合作、无尽、竞技场与宠物试炼仍走原固定流程。
- 房间类型：战斗、精英（难度提前一档，每三个敌人一个精英）、补给站、首领，以及三种新房间——事件（一次选择）、挑战（战斗加一条规则：限时 60 秒 / 护盾停转 / 精英潮 / 怪潮，成功后额外选一次 SR 起卡，限时超时则敌人消散、没有额外选卡）、宝藏（一小波怪，必出本图稀有怪，道具更多）。
- 选路方式（2026-11-10 改）：不再弹出路线面板。清场（或选完卡）后，如果下一层有分岔，房间中央会并排出现 2～3 扇不同颜色的传送门，门上只写房间类型（挑战的具体规则进门后看横幅），走进哪扇就去哪种房间：战斗银灰、精英橙红、补给绿、事件紫、挑战血红、宝藏金。补给站有分岔时，原传送门位置同样换成一排彩色门。同一层的房间类型互不重复，所以分岔总是真正的选择；有分岔的房间会预先清出中央一条通道放门。顶部房间进度条显示走过的房间类型，未走的显示问号，最后一格是首领。
- 事件房改为访客 NPC（PixelLab 生成的 96px 待机动画，见 tools/pixellab/create_npcs.py）：祭坛巫女、骰子狐、泉之精灵、宝箱怪。走近后访客头顶出现“按 J 交谈”，按攻击键打开对话（靠近访客时攻击键只交谈不射击），对话框带访客动态头像。
- 第一批事件：献祭祭坛（献祭：生命上限 -1 换 SR/SSR 选卡）、星砂泉（疗伤：回满生命和护盾；装星砂：带走 20 星砂，结算发放）、诅咒宝箱（打开：选卡，但之后敌人生命 +20%）。做出选择后访客道别，传送门打开。访客站在房间中心左侧 5 格（偏上 20），不挡住中央的单传送门或分岔传送门。顶部七个房间图标中，当前所在房间的图标块保持原尺寸与位置，只把边框改为黄色高亮（原 .cur 类与货币图标类冲突导致图标偏移，改用 .now）。
- 幸运骰子是掷骰小游戏：押单数或押双数，押注比例用骰子窗底部的比例条调节（30%～80%，每 10% 一档，拖动或点按时滑块吸附到最近一档，本次游戏期间记住上次比例，默认 50%），对话框以骰子为主体（标题与台词各一行，整体与头像等高；押单数/押双数靠左、离开靠右，与骰子窗左右对齐，按钮较短，两组之间留出明显空隙），大骰子翻滚弹跳约 1.5 秒后落定，大字显示点数和单双，押中赢回等额金币、押错输掉押注。事件对话框的彩色按钮文字使用单圈黑色描边（不用八向投影）。“离开”只关闭对话、打开传送门，可以再走回来接着玩；每个房间最多两轮，两轮用完或没有金币可押时只剩“离开”。
- 像素字库按源码重新抽字（tools/subset_font.py），这批新增的挑、骰、祭、坛、巫、女、泉、谈、押、例等字不再回退成系统字体。

## 运行 / 部署

```sh
npm install                                # 安装依赖（含打包工具 esbuild）
cd web && python3 -m http.server 8000      # 开发：直接用 ES 模块运行，打开 http://localhost:8000
./tools/build.sh                           # 打包到 dist/ 和 docs/（静态站点，约 19MB）
python test/update-integrity.py --git-ref HEAD # 检查构建与已提交文件是否符合热更新清单
```

构建会先将发布文本统一为 LF 换行，再生成大小与校验值；docs 的 Git 换行规则保持一致，避免 Windows 构建的清单与线上文件不符。更新失败时保留原版本和本机存档；修复发布后重新启动应用可再次更新，无需卸载。可用 `python test/update-integrity.py --url https://designer-awei.github.io/infinite-dream-preview/` 核验全部线上资源。

GitHub Pages：仓库 Settings → Pages → Deploy from branch → `main` / `docs`。
联机走 PeerJS（WebRTC 点对点，免费公共信令）；也可以 `?peer=你的域名:端口` 指定自建 PeerServer。`?local` 用 BroadcastChannel 在同一浏览器双开调试。
