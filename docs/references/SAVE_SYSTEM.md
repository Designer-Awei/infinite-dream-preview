# 存档码与模块快照

## 本轮核实结论（2026-11-27）

基线：预览仓 `32b40dc`、正式仓 `93f753c`。两仓的 save.js、lobby.js、world.js、home.js、runsave.js、petdata.js、main.js 字节一致。正式仓本轮只读，未修改。

- 大地图跨设备重置是已确认问题：旧 exportSave 只导出主键，地图、家园及续玩没有被收集。导入也只覆盖主键，因此还可能沿用目标设备另一玩家的地图、家园和续玩。
- 旧 IDSAVE1 的三段格式检查先于 JSON 内容检查；缺失末尾校验段会报“这不是无限梦境的存档码”，与是否有新版地图字段无关。正式仓历史中该格式从 `a24fd1b` 引入。
- 用户描述的异常样本在 codex 的 mine: 处截断，但本轮没有完整原始样本、导出设备、传输路径，不能判定在哪一环截断。
- 旧导出使用 `String.fromCharCode(...全部字节)`，高进度测试可复现参数过多的 RangeError。它会导致导出失败，不能据此声称是玩家截断样本的根因。
- 按本轮最终范围，只做存档码，不新增专用文件格式、文件选择器、分享插件、账号或服务器。玩家重新导出新的完整码后迁移；不尝试拼回旧码中从未导出的地图。

## 模块边界

`web/js/savemodules.js` 是统一模块注册表；运行时依旧分别存储，不把所有数据塞进一个键。

- `main` → `ai-girls-dungeon-v1`：晶石、角色、天赋、装配、经验、矿场、宠物仓库、图鉴、每日进度、称号等。
- `world` → `ai-girls-dungeon-world-v1`：探索迷雾、宝箱、传送门、首领/采集刷新、七种材料、旗标、裂纹岩、世界委托等。
- `home` → `ai-girls-dungeon-home-v1`：建筑及派遣槽、累计产出、派遣时间。
- `run` → `ai-girls-dungeon-run-v1`：未完成单人冒险的续玩检查点。

没有创建过的可选模块显式写为 `data:null`。导入时删除目标键，由现有加载器给出初始状态，不能保留另一玩家的数据。家园派遣已在 home 内，不虚构独立的派遣存储键。

更新缓存 `upd*`、调试地址及其他游戏数据不导出、不覆盖。备份库、事务记录、版本备份标记也不是玩家迁移模块。导出时若发现 `ai-girls-dungeon-` 前缀下有未注册的键，会停止导出，避免新功能遗漏进度。

新增玩家模块须在注册表提供 id、storage key、模块 version、名称、纯迁移函数。SaveManager 会自动收集、打包、校验、备份及整体替换；不需要重写导出界面。结构不兼容的模块须递增版本并补充迁移。

## 编码

`IDSAVE2.<Base64(Gzip(UTF-8 JSON))>.<SHA-256(Gzip字节)的小写十六进制>`

载荷包含 format=`infinite-dream`、envelopeVersion=`2`、saveVersion=`1`、gameVersion、exportedAt（UTC ISO 时间）和 modules。每个模块有独立 version 和 data。封装版本与玩家数据版本分别管理；元信息一起进入校验载荷。

Gzip 使用 fflate 0.8.3，SHA-256 使用 @noble/hashes 1.8.0 的纯 JavaScript 实现，避免依赖 LAN HTTP 环境不一定提供的 WebCrypto。浏览器构件位于 web/vendor/save-codec.js，许可证随包保留；`node tools/build-save-codec.mjs` 可由锁定依赖重建。Web 与 Android WebView 走相同代码，不增加原生插件或修改安装包身份、签名、版本。

1. 导出时先将主存档内存状态保存并回读，再同步读取全部注册模块，二次检查原始存储未变化。
2. 验证模块结构，构建快照，稳定序列化、Gzip、Base64、SHA-256。
3. 立即用真实导入解码器反向解码，按稳定 JSON 与原快照深比较；不一致时不提供存档码。
4. 复制后尝试回读：完全一致才显示“回读一致”。拒绝权限显示“未验证”；读回长度/内容不符显示“不一致”。不能自动复制时引导全选复制，不伪称已复制。

## 校验与安全覆盖

导入先验证格式、前后段完整性、Base64、SHA-256、Gzip、Gzip CRC/实际长度、JSON 结构、封装/数据/模块版本，再纯迁移并显示进度摘要。未知新模块或新版本拒绝导入。保持现有资产，迁移不调用发奖、结算或派遣计时函数。

限制：输入最多 12 MiB 字符、压缩载荷最多 4 MiB、解压 JSON 最多 8 MiB、深度最多 64、节点最多 500000。流式解压分小块提供输入，输出累计超限立即停止；检查 Gzip 尾部声明不是唯一防线。禁止原型污染字段。

用户确认覆盖后：先备份当前四模块并反向验证 → 写持久化恢复记录 → 替换全部目标模块 → 逐键及整体回读 → 标记完成 → 清理恢复记录。任一步失败，用导入前的原始字符串恢复全部模块；回滚仍失败时保留备份与恢复记录并阻止后续写入。下次启动在任何加载/迁移/保存之前恢复未完成事务。完成标记也核对目标哈希，不能将部分写入误判成功。

历史备份保留最近 6 份有效快照，逻辑编码总量上限 2 MiB，超限从最旧的有效备份移除。包括导入前、恢复前、版本更新前、每日启动及手动备份。空间不足以建立备份或恢复记录时，中止覆盖。历史备份仅在本机，卸载/清理数据会删除。

IDSAVE1 仍可验证原 FNV 校验后导入；它没有地图、家园、续玩，界面会提前提示这些模块从初始状态开始。没有这些数据就不能恢复它们；不继承目标设备的旧值。

`node test/save-system.mjs`：四模块往返、不同玩家覆盖、明确空模块清理、重复导入/迁移不变、未知模块防遗漏、格式/截断/损坏/版本拒绝、Gzip 长字面量及膨胀限制、11 组写入/回读/提交标记/清理/崩溃恢复场景、历史恢复与数量上限、更新前备份。

`PLAYWRIGHT_PATH=<现有Playwright包路径> node test/save-system-browser.mjs`：两个独立浏览器存储环境，实际界面预览及确认，导入重新加载后的四模块比对，真实 world/home/run 加载器比对，三种剪贴板回读状态，667/804/1280 宽度及无页面异常。PNG 与完整报告保存在忽略目录 `.cache/save-system/`。

`PLAYWRIGHT_PATH=<现有Playwright包路径> node test/save-system-built.mjs`（本地另以9878端口服务docs）：操作发布包中的真实“设置→导出/导入”按钮，重新加载后四模块完全比对。目标环境模拟Android壳，并移除WebCrypto，确认现有壳无需新增插件即可走相同编码链路；这不代表实体Android设备实测。

压缩实测使用与现有结构一致的合成样本，不是玩家原始样本：

- 普通：完整快照 7416 B → Gzip 2023 B（缩小 72.72%），IDSAVE2 共 2773 字符。
- 高进度（2500 只宠物）：完整快照 329082 B → Gzip 37244 B（缩小 88.68%），IDSAVE2 共 49733 字符；旧版仅主存档的 IDSAVE1 已达 436539 字符。

构建及发布清单使用 `npm run build`、`python3 test/update-integrity.py` 校验。没有实体 Android 设备实测，不能把桌面 Chrome 的移动视口或原生对象模拟称为实机验证。
