# 完整压缩存档码

## 当前范围

只提供存档码导出和导入。运行时的主进度、地图、家园、续玩继续各自保存；不增加历史存档、每日备份、更新前备份、启动恢复任务或专用存档文件。正式仓未修改。

旧版仅导出主存档，确定会漏掉独立存储的大地图。玩家需要在新预览版重新导出；当前导入只接受完整 IDSAVE2，不再维护 IDSAVE1 迁移。之前截图提示三段结构不完整，尚无原始文本及传输路径证据，不能断定截断环节。

## 模块化边界

`web/js/savemodules.js` 注册需要迁移的持久化模块。新增模块只需在此登记及添加结构检查，不必把运行时数据合并成一个键。

| 模块 | localStorage 键 | 内容 |
| --- | --- | --- |
| main | ai-girls-dungeon-v1 | 角色、晶石、天赋、宠物、矿场、图鉴、称号等 |
| world | ai-girls-dungeon-world-v1 | 迷雾、坐标、宝箱、传送门、材料、首领和采集记录、世界委托等 |
| home | ai-girls-dungeon-home-v1 | 建筑、派遣槽及累计产出 |
| run | ai-girls-dungeon-run-v1 | 单人冒险续玩检查点 |

四个模块必须全部出现在存档封装中；未创建的可选模块明确为 `data:null`。导入 null 时删除对应目标键，避免沿用另一玩家的地图和家园。更新缓存及设备配置不迁移。模块数据原样保存，导入校验不初始化字段、不结算奖励，现有游戏加载器继续负责运行时默认值。

## 编码和校验

`IDSAVE2.<Base64(Gzip(UTF-8 JSON))>.<SHA-256(Gzip字节)>`

封装包含格式版本、数据版本、导出时间、游戏版本和模块。Gzip 使用 fflate 0.8.3，SHA-256 使用 @noble/hashes 1.8.0，不依赖 WebCrypto 或原生新增插件。构件和许可证保留于 web/vendor；重建命令为 `node tools/build-save-codec.mjs`。

导出：保存最新主进度并回读 → 同步收集四个模块 → 检查结构 → 压缩及校验 → 使用真实解码器反向还原 → 与收集快照逐字段比较。通过后才提供完整存档码。

复制：在点击手势内全选完整文本，copy 事件显式提供全部存档码，避免依赖手机当前选中的片段；失败再尝试 Clipboard API。允许回读时逐字符核对；未获权限则明确显示未验证。导出界面只保留进度摘要、校验结果及存档码；复制结果使用简短提示，不显示技术元信息。导入失败显示收到字符数，便于定位传输丢失。

导入：检查三段格式、Base64、SHA-256、Gzip CRC、实际解压长度、JSON 和四个模块结构 → 显示进度摘要 → 用户确认覆盖 → 逐模块写入并回读 → 核对全部模块 → 重新加载游戏。同步写入失败时用本次调用内的原始字符串恢复，不持久化历史快照；不提供进程被强制结束时的事务恢复。

体积限制：文本12MiB、压缩载荷4MiB、解压JSON 8MiB，结构深度64、节点500000。解压流累计输出达到上限即拒绝，损坏或缺少校验值时不覆盖本机进度。

## 验证

- `node test/save-system.mjs`：四模块往返、重复导入资产不变、null清理、截断/篡改/版本拒绝、解压上限、5组同步写入/回读失败恢复、不新增历史存储键。
- `PLAYWRIGHT_PATH=<包路径> node test/save-system-browser.mjs`：源码页面的独立存储环境，导入重载与真实 world/home/run 加载器检查，完整码复制；二次确认连续打开和取消三次，复用单层静态遮罩并保留输入。
- `PLAYWRIGHT_PATH=<包路径> node test/save-system-built.mjs`：在9878端口服务docs，操作构建包的真实设置按钮，从手机触屏视口导出，经真实Chrome剪贴板和系统粘贴快捷键粘贴到独立电脑环境并确认导入、重新加载、逐字段比较四模块；含8及2500只宠物样本。即使先只选中部分文本，复制仍包含完整末尾校验段；截断码不允许覆盖。该测试未模拟剪贴板读写，但Android UA/壳及无WebCrypto环境为模拟，不能代替实体手机及第三方传输应用测试。

合成样本实测：7416 B → 2023 B（缩小72.72%）；2500只宠物样本329082 B → 37244 B（缩小88.68%）。它们不是用户原始存档。

构建及清单校验：`npm run build`、`python3 test/update-integrity.py`。测试截图和报告仅保留在本地忽略目录 `.cache/save-system/`。

## 存档弹窗布局

导出为“复制存档码 / 关闭”，导入为“覆盖存档 / 取消”，二次确认为“取消 / 确认覆盖”，每组按钮等宽。摘要使用三行三列网格，玩家名占两列；各列的字段标签定宽，数值与标签间隔8px、列间距18px。导入在空白时预留完整网格，解析只更新数值；校验状态区固定两行高度，空白、有效或错误不会改变窗口尺寸。存档码输入框四周保留聚焦轮廓空间，弹窗本身不滚动；输入框仍可浏览完整长码。二次确认复用导入遮罩，取消后恢复原输入面板，不叠加遮罩或重新播放变暗动画。

布局检查覆盖804×360、667×375、896×400和1280×720 CSS视口，包括等宽按钮、输入框轮廓空间、无容器滚动及空白/解析成功时高度相等。手机实体分辨率不等于CSS视口，以上为桌面Chrome触屏环境验证。
