# 素材入库规则

2026-11-09：按用户要求，仓库仅保存构建完整游戏需要的最终资源、最初参考图及已确认的设计替换图。制作中的全部原件继续留在本地，不删除工作目录。

- `web/assets/` 是最终运行素材的源码入口，保留配套 JSON、字体与许可。代码绘制的效果保留代码，不为其增加重复位图。
- `docs/assets/` 是现有 GitHub Pages / Android 构建使用的发布副本，属于必要产物。现有流程同时需要这两份，不在素材整理中修改 CI/CD 或删除其中一份。
- `art/references/` 保存原始参考图；`catalog.json` 记录 SHA-256、尺寸、用途与旧位置。同字节参考图只保留一份；最初设计和用户后来确认的新设计分别保留，不以新图覆盖历史原图。
- `art/` 的其他内容、仓库 `.cache/` 均忽略。生成任务返回、失败候选、raw 条带、逐帧图、裁片、缩放参考、动图、验收板、旧图集只留本地。最终图集已有的帧不重复入库。
- 原图→最终动画的方法见 [PixelLab 宠物动画流程](../references/PIXELLAB_PET_WORKFLOW.md)；当前采用的提示词、参数、裁切数据、清理记录与图集索引见同目录 `pet-animation-recipes.json`，按条查询，不整份加载。
- 新素材确认后先更新最终图集与元数据、对应配方和参考图目录，再执行 `python test/asset-policy.py`。不要强行添加被忽略的中间目录。
- 历史生成脚本和专项源图验收脚本可以保留作实现参考；需要本地 raw 的脚本不是构建依赖。全新下载的源码包应能直接构建，并能运行不依赖 raw 的 `test/asset-policy.py`。
- 不改写 Git 历史。取消跟踪会缩小新的源码 ZIP；历史提交仍保留旧素材和工作记录，完整 clone 的历史体积不会因此等比例缩小。
